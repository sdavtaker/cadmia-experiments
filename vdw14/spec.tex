\subsection*{Overview}

The tick-counter model from~\cite{VDW14} simulates a periodic tick source
counted over time and periodically reset.  A fast generator fires every
$1/10$\,s, a slow generator fires every $1$\,s, and a counter accumulates
ticks and outputs the count on each reset; ideally the count is $10$ at
every reset.  This experiment applies the IA-DEVS formalism~\cite{VDW21}
to the same model, replacing scalar time with interval arithmetic.
The enclosure guarantee mathematically ensures that causality errors are
eliminated~\cite{VDW21}; what we evaluate empirically is (i)~how much the
intervals grow over long runs---whether accumulated uncertainty remains bounded
or expands without limit---and (ii)~the computational cost of the interval
simulation compared to plain DEVS and PDEVS in practice.

% ─────────────────────────────────────────────────────────────────────────────
\subsection*{UA-DEVS Model}

The tick-counter is a coupled model
\[
  N = \langle X_N,\, Y_N,\, D,\, \{M_d\}_{d \in D},\, I,\, Z,\, \textsc{Select} \rangle
\]
with $D = \{G_{1/10},\, G_1,\, K\}$ and $X_N = \emptyset$ (no external input).

\subsubsection*{Generator $G_p$ (parametric)}

\[
  G_p = \langle S_G,\, T,\, \emptyset,\, Y_G,\;
        \delta^G_{\text{int}},\, \delta^G_{\text{ext}},\,
        \lambda^G,\, ta^G \rangle
\]
\begin{align*}
  S_G &= T \quad\text{(time elapsed since last event)}\\
  ta^G(s) &= p - s \quad\text{(remaining time to next event)}\\
  \delta^G_{\text{int}}(s) &= 0 \quad\text{(reset elapsed time)}\\
  \delta^G_{\text{ext}}(s, e, x) &= \text{undefined} \quad
    \text{(no external input; formally required but unreachable)}\\
  \lambda^G(s) &= \text{output signal}
\end{align*}

The initial state $s_0 \in T$ sets the elapsed time at simulation start.
Choosing $s_0 = 0$ schedules the first event at $t = p$; choosing
$s_0 \in (0, p)$ offsets the first firing to $t = p - s_0$, which can be used
to avoid synchronisation with other periodic components.

$G_{1/10}$ uses $p = 1/10$ and outputs a tick value of $1$.
$G_1$ uses $p = 1$ and outputs a reset signal.

\subsubsection*{Counter $K$}

\[
  K = \langle S_K,\, T,\, X_K,\, Y_K,\;
      \delta^K_{\text{int}},\, \delta^K_{\text{ext}},\,
      \lambda^K,\, ta^K \rangle
\]
\begin{align*}
  S_K &= \mathbb{N} \times \{\text{idle},\, \text{ready}\} \\
  ta^K(n, \text{idle})  &= \infty \\
  ta^K(n, \text{ready}) &= 0 \\
  \delta^K_{\text{ext}}\!\left((n,\text{idle}),\, e,\, x\right)
    &= \begin{cases}
         (n + x,\; \text{idle})  & x \neq 0 \quad\text{(tick)}\\
         (n,\;     \text{ready}) & x = 0    \quad\text{(reset signal)}
       \end{cases}\\
  \delta^K_{\text{int}}(n, \text{ready}) &= (0,\; \text{idle}) \\
  \lambda^K(n, \text{ready}) &= n
\end{align*}

\subsubsection*{Coupling}

Both generators route to $K$; $K$'s output becomes the coupled model output.
Coupling is expressed via influencer sets $I$ and translation functions $Z$:

\paragraph{Influencer sets.}
\begin{align*}
  I_{G_{1/10}} &= \emptyset \\
  I_{G_1}      &= \emptyset \\
  I_K          &= \{G_{1/10},\; G_1\} \\
  I_N          &= \{K\}
\end{align*}

\paragraph{Translation functions (Z).}
\begin{align*}
  Z_{G_{1/10},\,K}(y) &= y \\
  Z_{G_1,\,K}(y)      &= y \\
  Z_{K,\,N}(y)        &= y
\end{align*}

All three $Z$ functions are identity because every component shares the same
value type and signals are distinguished by value rather than by channel
(see Implementation Notes).  $I_N = \{K\}$ plays the role of the external
output coupling: $K$'s output is the output of the coupled model $N$.

\subsection*{Selected Approximations}

\paragraph{TIME type.}  \texttt{decimal<3>} (millisecond resolution).
All periods in this experiment are exact multiples of $1\,\text{ms}$,
so no rounding occurs and the outward-rounding invariant is satisfied
trivially.

\paragraph{Interval kind for periods.}  Point intervals.
The periods $p_{G_{1/10}} = 100\,\text{ms}$ and $p_{G_1} = 1000\,\text{ms}$
are assumed known exactly.  Choosing point intervals eliminates period
uncertainty from the model so that any causality error must arise from time
arithmetic rather than from model specification.

\paragraph{Interval kind for values.}  Point intervals.  Tick value $1$ and reset
signal $0$ are exact integers; both are represented as point intervals
$[1,1]$ and $[0,0]$.

% ─────────────────────────────────────────────────────────────────────────────
\subsection*{IA-DEVS Resulting Model}

With the approximations above, the IA-DEVS functions for each component are
given below.  Function names follow the IA-DEVS convention from~\cite{VDW21}:
$\mathrm{TA}$, $\Lambda$, $\Delta_{\text{int}}$, $\Delta_{\text{ext}}$ are
the interval-lifted counterparts of the scalar $ta$, $\lambda$,
$\delta_{\text{int}}$, $\delta_{\text{ext}}$.  Tilde ($\tilde{\phantom{n}}$)
denotes an interval-valued quantity.

\subsubsection*{Generator (IA-DEVS)}

State $\sigma \in \mathcal{I}(T)$ (interval of elapsed-time values).
For this experiment $\sigma_0 = [0,0]$; $\Delta_{\text{int}}$ resets to
$[0,0]$ after each event.

\begin{align*}
  \mathrm{TA}^G(\sigma) &= [p,\; p] - \sigma
    \quad\text{(interval subtraction; point for exact arithmetic)}\\
  \Delta^G_{\text{int}}(\sigma) &= [0,\; 0] \\
  \Lambda^G(\sigma) &= [v,\; v]
    \quad (v=1\text{ for }G_{1/10},\; v=0\text{ for }G_1)
\end{align*}

\subsubsection*{Counter $K$ (IA-DEVS)}

State $(\tilde{n},\, \text{mode})$ with $\tilde{n} \in \mathcal{I}(\mathbb{N})$
and $\text{mode} \in \{\text{idle},\, \text{ready}\}$.

\begin{align*}
  \mathrm{TA}^K(\tilde{n},\text{idle})  &= [\infty, \infty] \\
  \mathrm{TA}^K(\tilde{n},\text{ready}) &= [0, 0] \\
  \Delta^K_{\text{ext}}\!\left((\tilde{n},\text{idle}),\,
      \tilde{e},\, \tilde{x}\right)
    &= \begin{cases}
         (\tilde{n} + \tilde{x},\; \text{idle})  & 0 \notin \tilde{x} \\
         (\tilde{n},\;             \text{ready}) & \tilde{x} = [0,0]
       \end{cases} \\
  \Delta^K_{\text{int}}((\tilde{n},\text{ready}))
    &= ([0,0],\; \text{idle}) \\
  \Lambda^K(\tilde{n},\text{ready})
    &= \tilde{n}
\end{align*}

\subsubsection*{Expected output}

Because all intervals are point intervals and arithmetic is exact under
\texttt{decimal<3>}, every internal time is a point:
\[
  \tilde{t}^{G_{1/10}}_k = [k/10,\, k/10], \qquad
  \tilde{t}^{G_1}_k      = [k,\, k]
\]
At each integer second both generators are simultaneously scheduled;
after ten tick events the counter holds:
\[
  \tilde{n} = 10 \cdot [1,1] = [10,10]
\]
$K$ always outputs the point interval $[10,\,10]$.

\subsection*{Implementation Notes (CadmIA)}

\paragraph{Z-function encoding.}
UA-DEVS and IA-DEVS couple via Z functions, not ports; all three Z functions
in this model are identity (see Coupling above).  Both generators route to
$K$'s single \texttt{input\_t = int}.  The reset signal is encoded as value
$0$; any non-zero value is a tick.

\begin{center}
\begin{tabular}{@{}ll@{}}
  \toprule
  Interval value $\tilde{x}$ & Semantics for $K$ \\
  \midrule
  $[0, 0]$             & reset: output count, go to ready \\
  $\tilde{x}$, $0 \notin \tilde{x}$ & tick: add $\tilde{x}$ to accumulator \\
  \bottomrule
\end{tabular}
\end{center}

\paragraph{SELECT policy.}
At $t = [k,k]$ for integer $k$, both $G_{1/10}$ and $G_1$ are imminent.
$G_{1/10}$ must be selected first so that $K$ accumulates the $k$-th tick
before receiving the reset signal.  The \textsc{select} function is:
\[
  \textsc{select}(S) =
    \begin{cases}
      G_{1/10} & \text{if } G_{1/10} \in S \\
      G_1      & \text{if } G_1 \in S \\
      \text{first}(S) & \text{otherwise}
    \end{cases}
\]

\paragraph{Implementation status.}
Implemented and verified.  Across 100 resets, $K$ outputs $[10,10]$ at
every reset event (0 errors).  Source: \texttt{vdw14/main.cpp}.
